# 文章插画 / 正文配图构图规范

用户要求为文章、帖子、文档配插画时按本规范绘制。核心哲学：**一图一判断**——每张图只回答"这一段最想让人记住的一个判断"，把判断、流程、状态或隐喻画成一张白底黑线、怪诞但成立、一眼能读懂的手绘解释图。不是 PPT、不是正式流程图、不是装饰画。

## 〇、先选锚点（动笔前在思考里完成）

1. 通读全文，只挑**认知锚点**配图：核心判断、断点、输入输出闭环、分流、前后对比、常见坑、状态变化。
2. **不平均配图**：短文 1~2 张，长文 ≤ 4 张；没有锚点的段落宁可不画。
3. 用户只要"配图建议 / shot list"时，先出清单不落笔：每张写清——放哪段、核心意思、结构类型（见 §四）、小人做什么、2~5 个标注词。
4. 没有文章、只要一张独立插画（「画一张关于 X 的图」）时跳过本节——从要表达的那句话出发直接进 §一。本规范的画法（§二~§五）不限于文章。

## 一、画布与成组纪律

1. **保持白底**：不要调用 set_canvas_background——这套配图按白底黑线设计。
2. 单张：占满画布 (60,60)-(1540,940)，画面主体 ≤ 版面 60%，大量留白。
3. 多张：2 列网格（每张约 720×430，列 x≈50/830，行 y≈50/530），一张画完再画下一张；超过 4 张先问用户是否分批。
4. 不用 add_page——插画是画布上并排的区域，方便整组框选导出。
5. 全组不变量：同一小人模板、同一语义色映射、同一字号阶梯（标注 16~20、签名 14~16）。

## 二、演员与角色（一致性靠模板）

默认主角是一个**小黑式小人**：黑色实心圆头 + 实心胶囊身体、两粒白点眼、细线四肢、空表情（不画嘴）——认真做一件荒诞但成立的事。

1. 开工先在页面外暂存区（y ∈ [1100, 1500]）画「小人-站」（高 200~240、宽 90~120、元素 8~14：实心黑头、实心黑身、白点眼 ×2、四肢细线 stroke_width 2）→ save_template(name="小人-站", kind="character", ids=[...], delete_source=true)。
2. 每张插画用 stamp_template 盖章；小人必须**承担核心动作**（卡在机器里、拉杆、搬运、守门、称重、接东西），禁止站旁边当装饰。
3. 剧情需要的动作姿势现场补建：暂存区按同一套配色画新姿势（用 pose_element 掰肢体或直接画开）→ 同名 save_template 入库 → 再盖章。禁止拿站姿硬凑动作。
4. **尺度夸张**：放大物件、缩小小人——小人高度 ≤ 画面主体物件的 1/3、≤ 版面高度的 1/10。戏剧感来自落差。
5. **故事类内容用故事角色当演员**：画寓言、故事、案例时，讲解员退位，让故事角色演（小马过河就画马、牛、松鼠，不插小人）；多个角色各画一套并 save_template 入库，**辨识三件套**（轮廓剪影 / 主色 / 标志特征）至少两维拉开——否则小马和老马同框就分不清谁是谁。
6. **说话者必须在场**：对白、内心话用 draw_speech_bubble（speech=对白 / thought=内心独白 / burst=惊叫巨响），**气泡尾巴指向说话者，且说话者必须画在图里**——台词悬空等于没有出处；立场类短标注（如「河水很浅」）才用彩色字挂在说话者头顶。

## 三、隐喻发明法（每篇文章重新发明，禁照搬旧图）

1. 三步把抽象概念变成画面：
   - 抽象概念 → **物理动作**：卡住、漏掉、变重、分拣、沉淀、发酵、折叠、回流；
   - 系统结构 → **低科技物件**：纸箱、漏斗、水管、邮筒、抽屉、井、梯子、秤、怪机器（一次只用 1~2 个，不堆满）；
   - 小人承担动作：拉、扛、塞、捞、压、称、守、推、接、拆、标记。
2. **域物件优先**：专业内容（数学、工程、医学）画领域内物件（坐标系、数轴、管线、仪表、烧瓶），不套万能隐喻。
3. **慎用象征**：放大镜（查找）、灯泡（灵感）、齿轮（机制）、时钟（效率）、钥匙（方案）——仅原文确有该语义时才用。
4. 同类主题换新隐喻：这次画过"漏斗分拣"，下次同一概念就换物件换动作——换一篇内容还成立的图，就是模版。

## 四、结构类型（每张选一种）

1. **流程闭环**：左输入 → 中处理（小人在里面操作）→ 右输出，橙色弯箭头标主流向。
2. **前后对比**：左混乱右稳定，中间一条弯箭头，两区高低错落，不要对半切开。
3. **角色状态**：2~4 个小状态，每个状态一个短标注。
4. **概念隐喻**：一个大的怪物件，少量输入一个输出，要有记忆点。
5. **方法分层**：一层层盒子往上摞，别画正式金字塔。
6. **路线地图**：一条弯曲路径 + 少量节点，小人在路上走。
7. **小分镜**：2~3 格，每格只表达一个动作。

## 五、画面铁律

1. **平衡优先于序列**：围绕一个视觉重心组织，元素分散在两轴 3~5 个区，大主体旁 2~3 个小配重；只有流程主题才用横向，且节点错落高度，禁止全部排在一条水平线上。
2. **流线纪律**：箭头用主色、比物件轮廓更细；一条弯曲线（多点 draw_arrow polyline）优于多条直箭头；只给主路径画箭头。
3. **语义色**（全组一致）：橙 0xE8590C=主路径/动作箭头，红 0xC92A2A=问题/重点/结果，蓝 0x1A5FD7=补充/系统状态；每张彩色 ≤ 3 处，其余全部黑白灰（线 0x1e1e1e、灰 0x868e96）。
4. **标注纪律**：每张 2~5 个短标注（draw_text handwritten、16~20），细线指引挂在动线节点上；禁止大段文字入图、禁止图内出现"流程图/架构图"式左上角标题。
5. **签名位**：每张左下角一条 40 长橙色短横线 + 下方一行 14~16 灰字——这张图的判断句。判断句要一句话可复述、点破画面张力或结论，避免同语反复（「别人的深浅是别人的深浅」式绕句）与照抄正文原句；关键词用字与图内标注一致（统一写「蹚」就全组都是「蹚」，不混「趟」）。位置样式全组一致。
6. roughness 保持画布默认 1.0（别传 0），手绘感来自抖动线条与排线，文字照常排正。

## 六、完成自检

全部画完后调用一次 list_elements 终检（过程中不要反复调）。

**必过项**：一张图一个核心结构；小人承担动作；标注少而短、挂节点；彩色 ≤ 3 处且语义正确；签名位每张在场。

**失败信号**（任一命中即修）：左上角有图题；小人只是站着；满页直线箭头；元素排成一条水平直线；画面像正式流程图/PPT（整齐网格、边框）；节点太多、文字变段落。

**迭代映射**：太普通 → 让小人做一个奇怪但成立的动作；太复杂 → 删节点，只留一个动作 + 3~5 个标注；太乱 → 检查阅读动线，主线是否唯一、标注是否挂在线上。

## 七、嵌入其他场景时

PPT、黑板报等其他场景进行中被要求画插画时，本规范的**方法论照用**（小人模板、隐喻发明、画面铁律、自检），但版式向宿主让位：

1. 底色与配色遵守宿主规范：PPT 用该篇的主色系统（语义色的"橙=路径、红=问题、蓝=补充"映射不变，色值可向主色系靠拢）；黑板报用粉笔高亮色（白/米黄/粉/浅蓝/浅绿/浅黄），禁黑色描边与文字。
2. 尺寸按宿主版面缩放：PPT 页内插画 ≤ 版面 40%，黑板报板块内 ≤ 板块面积 1/3；省略签名位与多张网格。
3. **跨载代价**：本技能被 use_skill 加载后即成为"活动技能"，宿主规范会退出下一轮运行时上下文——**画完继续宿主制作前，重新 use_skill 加载宿主规范**（slides / blackboard-poster）。
4. 小幅随文涂鸦不需要跨载：各场景技能自带的插图规则（slides §四、blackboard-poster §6）更贴它们自己的视觉身份，优先用。
