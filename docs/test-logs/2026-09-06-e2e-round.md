**真 bug #1（产品）：macOS 上 Cmd+Z 无绑定。** E2E-007「撤销还原像素」永远不过；
应用侧调试日志证明事件已到达。查 `main.rs` 键表：编辑命令族只绑了 Windows 风格
`ctrl-*`（undo/redo/save/open/插入图片/层序/缩放/AI 面板/设置 全部中招）。
按既有 cmd-q+ctrl-q 并存模式补齐全部 Cmd 变体（cmd 修饰键在 Windows 不存在，
绑定天然不触发，零风险）。修复后 E2E-007 PASS。
（注：Ctrl+Z 在 macOS 上一直可用，故日常未暴露。）

**真 bug #2（harness 阻断级）：坑 3 的 ABI 错误。** 按计划里「未实跑不合并」的

# 追加轮 — 渐变填充真机不显示（E2E-003 前哨战）

> 症状：选中椭圆点「渐」+ 黄色底，画布上只有描边、内部纯白（像素实测
> 100% 白）；面板「渐」高亮正常。用户报告「明明是已经改好了的」。

## 分析过程（逐层排除）

| 层 | 验证方式 | 结论 |
|---|---|---|
| 数据 | 读盘 `未命名 16.boundless`：`background=0xffd949, fill_style=gradient` | ✅ 正确 |
| 指纹 | cache.rs 覆盖 background/fill_style/brush 全字段 | ✅ 缓存会失效 |
| 几何 | 用用户真实元素（含 seed/飞白笔刷）跑 `world_geometry` | ✅ 出图 |
| 绘制 | `paint_world_geom` → ReadyPath | ✅ 出图 |
| 路径面积 | gpui Path Debug 顶点解析：240 顶点、x 143-385 / y 14-161 | ✅ 有面积 |
| **真机渲染** | **FillPath+渐变上屏 = 不可见**（描边正常） | ❌ **根因** |

根因：gpui 0.2.2 的 `PathBuilder::fill()` 产物在真机上不可见 —— Windows 侧
早有最小复现工程（fill_repro）证实，注释里写着「macOS 着色器原生支持渐变」
只是**读码推断，从未上屏验证**（当晚设备锁屏，test-plan 的 harness 骨架也是
同样的锁屏提交）。全 App 其他填充样式（实/水彩）都刻意绕开 FillPath，渐变是
唯一使用者的，也就是唯一翻车的。单元测试全绿是因为它们只覆盖 CPU 侧镶嵌，
最后一跳（Metal 光栅化）单测天然测不到。

## 修复

渐变改走全 App 验证过的 **FillSketch→stroke 排线管线**（`rough.rs`）：

- `options_for`：渐变不再映射 Solid/FillPath，与其他样式一样出 Hachure 排线；
- `fill_params` 渐变参数：密排重叠（线宽 ≈ 2.2× 间距，无缝）；
- `rough_shape` 新增 Gradient 臂：roughr 把整片排线装在一个 OpSet 里，
  按 MoveTo 拆成每线一个 OpSet，按线中点 y 在 lighten(35%)→darken(35%)
  之间 `lerp_hsla` 逐线上色（PaintOverride）；
- 期间抓到并修复自身引入的 bug：ymid 分母误用全元素数（含 ClosePath），
  被新回归测试当场拦下。
